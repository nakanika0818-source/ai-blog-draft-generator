# 案件2：GAS＋AIブログ記事自動生成

Googleスプレッドシートのカスタムメニューから、選択した1行のキーワードで記事を生成し、シートへ保存します。WordPressへは下書きとして送信できますが、初期設定では実送信しません。自動公開の機能はありません。

## まず読むもの

| やりたいこと | 読む資料 |
|---|---|
| APIキーを設定する | [設定手順 B. Claude APIキー](docs/01_設定手順.md#b-claude-apiキー)（スプレッドシートとコードの準備は同じ資料のA） |
| 記事を生成する・事実確認する・送信内容を確かめる | [使い方](docs/02_使い方.md) |
| エラーが出た・止まった | [トラブル対処](docs/03_トラブル対処.md) |

APIキーは、Apps Scriptのスクリプトプロパティだけに保存します。コード、シート、チャット、メール、スクリーンショットには載せないでください。

## シート構成

シート名は `記事管理` です。文体サンプルは別シート `文体サンプル` のA2以降に置きます。

| 列 | 見出し | 書き込む人 |
|---|---|---|
| A | キーワード | 人 |
| B | サブキーワード | 人 |
| C | ステータス | スクリプト |
| D | タイトル | スクリプト（確認後に人が編集可） |
| E | WordPress URL | スクリプト |
| F | 記事本文（HTML） | スクリプト（確認後に人が編集可） |
| G | メタディスクリプション | スクリプト（確認後に人が編集可） |
| H | 事実確認（人が記入） | 初期値 `未確認` のみスクリプト。`確認済み` は人だけが記入 |
| I | 要確認事項 | スクリプト |
| J | WordPress投稿ID | スクリプト |
| K | 失敗工程 | スクリプト |
| L | エラー内容 | スクリプト |
| M | 生成モデル | スクリプト |
| N | 更新日時 | スクリプト |

H〜N列は仕様の「必要なら追加」に基づく管理列です。

## ステータスの流れ

```
（空）──生成──▶ 生成中 ──▶ 生成済み ──投稿──▶ 投稿中 ──▶ 投稿済み（下書き）
                  │          ▲                 │
                  ▼          │                 ├─ 作成されていないと判断できる ─▶ 投稿失敗 ─▶ 再投稿可
               生成失敗 ─────┘                 └─ 作成された可能性がある ─────▶ 投稿結果不明
              （再実行可）                                                     （人が確認して確定）
```

## 設計上の判断

| 判断 | 理由 |
|---|---|
| `まとめ` もH2にする（本論H2×3＋まとめH2の計4個） | 仕様「導入→H2×3→まとめ」の解釈。まとめ見出しは固定で検証の対象外にしている。H2以外にする場合は `buildArticleHtml_` と `validateArticleContent_` の変更が必要 |
| 文字数は「タグと空白を除く、見出し込みの可視文字」 | 仕様に定義がないため明文化した。メタディスクリプションは前後の空白を除いた全文字 |
| AIにはHTMLを書かせない | プレーンテキストで受け取りコード側でエスケープする。不正なHTMLやスクリプトの混入を防ぐ。代わりに初期版では段落と見出しのみで、箇条書きやH3はない |
| 投稿時も検証を再実行する | 人が編集した本文も、送信前に文字数と構成を確認する |
| 検証違反は1回だけ自動で作り直す | 文字数のずれは起きやすいため。費用は最大2回分になる。`GEN_MAX_ATTEMPTS=1` で無効化できる |
| 事実確認が `未確認` でも下書き投稿は止めない | 下書きは公開されず、WordPress上で確認する運用もあるため。投稿前の確認ダイアログで警告する |
| 既定モデルは `claude-opus-5-5`、effortは `medium` | 公式資料が最初の選択肢として推奨。`CLAUDE_MODEL` と `CLAUDE_EFFORT` で変更できる |
| 拒否時のフォールバック（`fallbacks: "default"`）を有効にする | 安全分類器の誤判定で失敗しにくくするため。ベータ機能で、別モデルが応答する場合がある（M列に記録）。`CLAUDE_FALLBACKS=off` で無効化できる |

## 既知の制約

- WordPressのREST APIには重複投稿を防ぐキーがないため、結果不明の行は人の確認が必要です。
- `要確認事項` は補助です。検出されなかった記述が正しいという意味ではありません。
- 転載検査はサンプルとの25字以上の完全一致のみ検出します。言い換えた転載や構成の流用は検出できません。テスト用キーワードのうち、サンプルと題材が重なるものは、人の確認を重点的に行ってください。
- 応答はストリーミングせず一括で受け取ります（`UrlFetchApp` の仕様）。実行時間は1回あたり約5分半で打ち切ります。
